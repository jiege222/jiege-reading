# 杰哥阅读：MVP 技术方案

版本：1.0｜日期：2026-09-17

依据：docs/产品设计-MVP.md。本文确定第一版的实现方向、关键技术决策和验证范围，不展开完整接口及组件设计。

## 1. 目标与范围

实现适配电脑和手机浏览器的本地 TXT 阅读器，完成“导入 → 书架 → 阅读 → 自动续读”的完整流程。书籍、进度和设置保存到当前浏览器，无需登录，无需业务后端。

第一版包括 UTF-8 / GBK 导入、编码手动切换、书架排序与删除、滚动阅读、字号与行距、浅色与深色主题、本地保存和按书续读。

不包含章节目录、书签、搜索、笔记、EPUB / PDF、云同步、AI、朗读和翻页动画。第一版不引入 Electron，也不提前建设这些功能的系统。

## 2. 技术栈与选择理由

| 层次 | 选择 | 用途与理由 |
| --- | --- | --- |
| 界面 | React + TypeScript | 组织书架、阅读页和设置；明确书籍、进度和存储操作的数据类型 |
| 构建 | Vite | 提供开发服务和静态资源构建；项目不需要服务端渲染 |
| 存储 | IndexedDB + idb | 异步保存正文及元数据；idb 简化 Promise 和事务操作 |
| 阅读排版 | CSS + TanStack Virtual | CSS 控制主题和排版；按文本块进行动态高度虚拟渲染 |
| 编码处理 | TextDecoder + Web Worker | 使用浏览器编码能力；将解码和分块移出主线程 |
| 测试 | Vitest + Playwright | 验证文本与进度逻辑，以及浏览器中的完整使用流程 |

界面状态先使用 React 自带能力，不额外引入全局状态库或大型组件库。以 npm 管理依赖并提交锁文件；实施时选择相互兼容的稳定版本，不在本文写死版本号。

IndexedDB 适合本项目的本地数据量，但不是备份机制。浏览器数据清除、更换浏览器或设备、隐私模式和存储回收都会影响保留情况。[参考 1、2]

## 3. 整体结构与数据

应用分为界面层、阅读与导入逻辑层、存储层。界面不直接操作数据库，通过少量存储函数执行导入、读取、保存和删除，以便测试和维护。

建议目录：src/pages 放书架与阅读页；src/components 放设置和通用界面；src/reader 放分块与定位逻辑；src/import 放编码和 Worker；src/storage 放数据库与事务；tests 放功能测试。

| 数据 | 主要字段 | 保存方式 |
| --- | --- | --- |
| books | id、书名、编码、原文件字节数、导入时间、最近阅读时间、正文长度、块数量 | 书籍元数据；按最近阅读时间排序 |
| blocks | bookId、blockIndex、startOffset、text | 以 bookId + blockIndex 为联合主键；正文分块保存 |
| progress | bookId、textOffset、updatedAt | 每本书独立保存内容锚点 |
| settings | 固定 id、fontSize、lineHeight、theme | 全局阅读设置；加载时检查范围与默认值 |

正文统一换行为 LF，去除开头 BOM，不改写原有段落和空行。textOffset 使用规范化正文的 UTF-16 索引，与 JavaScript 字符串及 DOM 文本偏移保持一致；切块与定位时避免拆开代理对。

导入完成前先生成全部待存数据，再用一个覆盖 books、blocks、progress 的 IndexedDB 事务提交。事务完成后才显示“导入成功”，避免保存出半本书。事务中不穿插解码或无关异步任务。

删除前确认；用事务同时清理该书的元数据、正文块和进度。删除失败保留列表并提示重试。数据库从 schema version 1 开始，后续升级必须通过迁移保留已有书籍，不直接清库。

## 4. 关键实现决策

### 4.1 TXT 导入与编码

通过文件选择器读取本地文件，按扩展名检查 TXT；文件 MIME 仅作辅助，因为系统可能不提供可靠类型。空文件、解码后只有空白的文件、明显包含大量二进制控制字符的文件给出明确提示。

编码选择：UTF-8 BOM 优先；没有 BOM 时先进行严格 UTF-8 解码，失败后尝试 GBK。解码成功不能证明编码判断一定正确，允许在导入确认界面手动切换 UTF-8 / GBK，并预览正文。[参考 3]

切换编码使用本次选择的原始字节重新解码；确认后保存选定编码和规范化正文。第一版不额外永久保存原始文件字节，已入库书籍若需要重新解码，可删除后重新导入；界面提示用户保留原始 TXT。

文件读取、解码和分块在 Worker 中完成，向主线程返回进度和结果。界面显示处理状态并防止重复提交。失败时保留可重试入口，不把未完成导入的书加入书架。

### 4.2 长篇小说与滚动阅读

按段落边界生成约 2,000～4,000 字符的文本块；单段过长时再拆分，并记录连续的正文偏移。分块只是性能单位，不增加章节识别功能。

使用 TanStack Virtual 渲染视口附近的文本块，保留少量预渲染内容；按实际排版测量块高度。正文按需从 IndexedDB 读取，并限制内存缓存，不为每次打开书籍读取和渲染全部正文。[参考 4]

字号、行距或容器宽度变化时，重新测量高度并恢复正文锚点，避免仅依赖旧高度估算。用长文本验证快速滚动、滚动条跳转和块边界，重点观察空白、跳动及进度偏移。

Worker 和虚拟渲染分别降低主线程计算和 DOM 开销，不代表内存无限：导入时仍需处理原始字节、解码文本和待存块。以实测决定后续是否需要流式导入，不先建设复杂流水线。

### 4.3 自动续读与排版变化

进度记录视口正文顶部附近的 textOffset，不把 scrollTop 当作唯一进度。利用已渲染块的起始偏移和 DOM Range 测量，确定当前可见文本位置；滚动时限制测量频率。

恢复时，先根据偏移找到文本块并滚动到附近，待块渲染、字体和布局就绪后，再通过文本位置校正。调整字号、行距或窗口宽度前保存当前锚点，重排完成后定位到同一处正文。偏移越界时安全截断到正文范围。

滚动过程约每 1 秒节流保存一次最新进度，并按书串行提交，避免较旧写入覆盖新位置。返回书架前等待进度保存；切换到后台时尝试立即保存。

不能依赖关闭事件保证 IndexedDB 异步写入完成。正常关闭后恢复到最近已完成保存的正文附近；浏览器被强制结束时可能损失最近约一个保存周期的进度，测试和界面表述均不承诺零丢失。

### 4.4 设置、本地保存与异常

设置调整即时应用，短暂防抖后入库；保存失败时保留当前显示效果，并明确提示设置尚未保存。正文采用纯文本渲染，不将书籍内容作为 HTML 插入。

将 QuotaExceededError、数据库打开失败和事务失败转换成可理解的提示。配额不足时提示删除不需要的书或释放浏览器空间，不自动删除用户书籍。[参考 2]

浏览器支持时可检查存储容量，并在适当时机尝试 navigator.storage.persist()。授权结果不确定，不作为导入前提，也不能阻止用户主动清理数据。遇到数据库版本升级被其他标签页阻塞时，提示关闭旧页面后重试。

手机端设置正文最大宽度、合理边距和长行换行；按钮保持易点按，保留浏览器缩放。提供明确的加载、空书架、错误和保存状态。

## 5. 运行与交付方式

开发时运行 Vite；生产构建为静态资源，通过 HTTPS 静态站点提供访问，不需要业务后端。书籍文件和正文不上传到服务器，第一版不加入第三方埋点。

使用固定访问地址：IndexedDB 按来源隔离，更换协议、域名或端口会访问不同的数据空间。生产部署不使用直接双击 file:// 页面作为正式运行方式。[参考 2]

目标为现代桌面 Chrome、Edge、Firefox、Safari，以及 Android Chrome、iOS Safari。Playwright 覆盖主要浏览器引擎和移动视口，另在真实手机验证文件导入、滚动和后台恢复，模拟器不能替代全部真机行为。

本地保存不等于页面离线可用；本版不承诺断网后重新启动页面。若后续明确需要安装入口和离线启动，再补充 PWA 与 Service Worker 缓存策略。

## 6. 实施顺序与验收

1. 建立 React + TypeScript + Vite 工程、数据库结构和测试入口，完成 UTF-8 / GBK 导入与书架。
2. 完成分块读取、虚拟阅读、字号行距和主题；用长文本验证动态高度与滚动体验。
3. 完成内容锚点续读、排版恢复、事务删除和异常提示。
4. 完成跨浏览器与真机验证，再做构建和交付检查。每个完整改动同步更新测试并创建 Git commit。

| 验证项目 | 主要用例与通过条件 |
| --- | --- |
| 导入 | UTF-8、UTF-8 BOM、GBK、CRLF / LF、手动切换编码、空白文件、非 TXT、读取失败；正文正确，错误提示清晰 |
| 分块与定位 | 拼接块能还原规范化正文；块偏移连续；长段、空行、中文及 emoji 不损坏；锚点与正文位置对应 |
| 本地事务 | 导入写入中断后不出现残缺书籍；删除清理该书全部数据；故障及配额不足提示正确 |
| 多书续读 | 两本书独立保存；刷新及正常重新打开后恢复；改变字号、行距和视口后仍看到原锚点附近正文 |
| 阅读设置 | 设置生效并在刷新后保留；非法旧数据回退默认值；保存失败有提示 |
| 长文件 | 用约 1 MiB、10 MiB 的 UTF-8 / GBK 样本覆盖正常阅读，约 50 MiB 作为压力测试；记录导入与打开耗时、内存和滚动表现 |
| 手机与浏览器 | 正文无横向溢出；操作可点按；真实手机可选文件、阅读、切后台和重新进入 |

上述文件大小是测试样本，不是已承诺的容量上限。实施阶段记录设备及浏览器版本，在 10 MiB 样本上以打开约 2 秒内、交互无持续阻塞作为初始优化目标；正式验收仍以产品文档的阅读体验要求为准，压力测试用于识别边界。

Vitest 覆盖编码策略、分块、进度映射、设置和存储失败逻辑；事务测试可使用 fake-indexeddb 辅助。Playwright 必须在真实浏览器 IndexedDB 上验证导入、刷新续读、设置及删除，不仅依赖内存模拟。

交付前执行 TypeScript 检查、全部单元测试、端到端测试及生产构建，并运行 tests 下全部文档验证脚本，包括 verify-agents.ps1。实现时在 package.json 中统一提供相关命令。

## 7. 风险与后续方向

第一优先级是动态高度下的滚动稳定性和续读准确性，应尽早做长文件原型验证。编码识别保留人工纠错；浏览器存储保留原文件提示，并明确不能跨设备自动同步。

若后续转向桌面独立软件，可以复用 React 阅读界面和纯文本处理逻辑，通过存储层适配 Electron 的本地文件或数据库。桌面打包、文件关联和更新属于后续工作，不在本版提前实现。
